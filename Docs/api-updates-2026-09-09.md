# API updates - OpenAI GPT-Image-2.5 (2026-09-09)

Research date: 2026-09-09, the day after the GPT-Image-2.5 launch. Method: Firecrawl scrapes of the announcement, the developer docs (models, image-generation guide, API reference, pricing, deprecations), the Codex docs, and the openai/codex source (raw captures in `.firecrawl/`, not committed). No live API calls were made.

## Confirmed model IDs

| Marketing name | API model ID | Dated snapshot | Source |
|---|---|---|---|
| GPT-Image-2.5 Flare (fast) | `gpt-image-2.5-flare` | `gpt-image-2.5-flare-2026-09-08` | https://developers.openai.com/api/docs/models/gpt-image-2.5-flare |
| GPT-Image-2.5 Sunburst (most capable, slower) | `gpt-image-2.5-sunburst` | `gpt-image-2.5-sunburst-2026-09-08` | https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst |

The naming maps as the owner expects: Flare is the fast default ("Speed: Very fast"), Sunburst is the precision model ("Speed: Medium", "Our most capable model for image generation and editing"). Both share one envelope: quality `low, medium, high, xhigh, max, auto`; recommended sizes `1024x1024`, `1536x1024`, `1024x1536`; custom `WxH` with edges divisible by 16, ratio 1:3 to 3:1, max edge 3840, 655,360 to 8,294,400 pixels; b64 output only; `background` opaque or transparent (png/webp); `moderation` auto or low; `n` 1 to 10; `partial_images` 0 to 3 for streaming. Pricing is the same for both: $8/M image input, $2/M cached image input, $30/M image output, $5/M text input, $1.25/M cached text input (https://developers.openai.com/api/docs/pricing#image-generation).

## What this branch changed

Both models in the API-key route, `gpt-image-2.5-flare` as the default (aliases `flare`, `2.5`), `-m sunburst`, `-m image2` (plus the existing `2`) for `gpt-image-2`, and `xhigh`/`max` accepted on the 2.5 models only. The subscription route keeps serving `gpt-image-2` and refuses an explicit 2.5 pick (see items 1 and 2).

## Where the repo is behind, one line each

1. **Subscription route and the 2.5 models are unverified.** The Codex docs still say built-in image generation "uses `gpt-image-2`" (https://learn.chatgpt.com/docs/image-generation) and the Codex CLI hardcodes `IMAGE_MODEL = "gpt-image-2"` (https://github.com/openai/codex/blob/main/codex-rs/ext/image-generation/src/tool.rs); nothing published shows the Codex backend accepting a 2.5 model in the tool. What it would take: one live subscription call with `tools[0].model = "gpt-image-2.5-flare"`; on a 2xx flip `Subscription: true` on the two rows of `modelSpecs` in `providers/openai/options.go`.
2. **Responses API reference is stale versus the guide.** The `image_generation` tool's `model` enum in the reference lists only `gpt-image-1` through `gpt-image-2-2026-04-21` and `chatgpt-image-latest` (https://developers.openai.com/api/docs/api-reference/responses/create), while the guide passes `gpt-image-2.5-sunburst` in that same tool (https://developers.openai.com/api/docs/guides/image-generation#generate-images). What it would take: nothing in code; it is the reason item 1 cannot be settled from docs alone.
3. **`background: transparent` is now a first-class option.** Both 2.5 models "support `opaque` and `transparent` backgrounds" and `gpt-image-2` has it "in preview" (https://developers.openai.com/api/reference/resources/images/methods/generate); the repo's `--background` enum is `auto, opaque` after the earlier removal. What it would take: add `transparent` to the enum, a `Backgrounds` column in `modelSpecs` gating it per model, and a check that `-f` is png or webp.
4. **Dated snapshots are rejected by `-m`.** `gpt-image-2.5-flare-2026-09-08`, `gpt-image-2.5-sunburst-2026-09-08` and `gpt-image-2-2026-04-21` are valid model IDs (https://developers.openai.com/api/docs/models/gpt-image-2.5-flare) but the `@models` enum only knows the undated IDs. What it would take: a `Snapshots` list on each `modelSpec` row surfaced through `DeprecatedAliases` (resolves, not advertised).
5. **Edits endpoint documents a JSON body and a 16-image cap.** The reference now shows `images[]` entries of `{file_id, image_url}` and says "For GPT image models, you can provide up to 16 images" (https://developers.openai.com/api/reference/resources/images/methods/edit); the repo sends multipart `image[]`, which the curl examples on the same page still use. What it would take: nothing for correctness; optionally reject more than 16 references client-side.
6. **`input_fidelity` on edits.** The edits reference lists `input_fidelity: high | low` with no per-model note (https://developers.openai.com/api/reference/resources/images/methods/edit); the guide only says to omit it for `gpt-image-2` and is silent on 2.5 (https://developers.openai.com/api/docs/guides/image-generation#image-input-fidelity). The repo omits it everywhere. What it would take: a live edit call on `gpt-image-2.5-flare` with `input_fidelity=high`; if accepted, a gated `--input-fidelity` flag.
7. **Streaming on the Image API.** `stream: true` plus `partial_images` 0 to 3 is documented on both `/images/generations` and `/images/edits`, each partial costing 100 extra output tokens (https://developers.openai.com/api/docs/guides/image-generation#streaming). The API-key route is request/response only. What it would take: an SSE reader on the API-key route mirroring `parseImageStream`, and a `--partial-images` flag.
8. **Responses tool gained `action`.** `action: generate | edit | auto` controls whether the tool edits an image already in context (https://developers.openai.com/api/docs/guides/image-generation#multi-turn-image-generation); the subscription route relies on the prompt alone. What it would take: set `action: "edit"` when references are attached, after a live check that the Codex backend accepts the field.
9. **2.5 token rates are double gpt-image-2's.** $8/$2/$30 per million image input/cached/output tokens versus $4/$1/$15 for `gpt-image-2`, and OpenAI warns "Equal token rates don't mean equal cost per image" with no per-image price table for 2.5 (https://developers.openai.com/api/docs/guides/image-generation#cost-and-latency). What it would take: a pricing note in `skills/imagine-cli/references/openai.md`; nothing in code.
10. **The `4K` shorthand lands in the experimental band.** "Resolutions above `2560x1440` are experimental" for all three models (https://developers.openai.com/api/docs/guides/image-generation#size-and-quality-options); `-s 4K` maps to `3840x2160`. What it would take: one line in the SIZES help block.
11. **Model pages say "Streaming: Not supported".** Both 2.5 model pages list streaming as unsupported under Features while the guide and reference document `partial_images` streaming for them (https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst). What it would take: nothing; a docs inconsistency to remember when reading item 7.
12. **Rate limits are per-image and low at Tier 1.** 5 images per minute at Tier 1, 20 at Tier 2 (https://developers.openai.com/api/docs/models/gpt-image-2.5-flare); `-n 10` or a parallel batch file can trip that immediately. What it would take: nothing in code; a note in the batch docs.
13. **Prompt cap is 32,000 characters.** "The maximum length is 32000 characters for the GPT image models" (https://developers.openai.com/api/reference/resources/images/methods/generate); the repo does not check it. What it would take: a client-side length check in `Options.Validate`.
14. **Nothing new deprecated.** The deprecations page still lists only the 1.x family and `chatgpt-image-latest` (shutdowns Oct 23 and Dec 1, 2026), already removed from this repo; `gpt-image-2` has no deprecation notice (https://developers.openai.com/api/docs/deprecations). What it would take: nothing.
15. **Still correct.** `moderation_details` on `moderation_blocked` errors (https://developers.openai.com/api/docs/guides/image-generation#handling-blocked-requests-and-other-errors), the size envelope, `n` 1 to 10, b64-only output, `output_compression` on jpeg/webp. What it would take: nothing.

## Is the current provider already broken against today's API?

No. Every parameter the API-key route sends (`model, prompt, n, size, quality, output_format, output_compression, moderation, background`) is still documented for the GPT image models on both endpoints, `gpt-image-2` is neither deprecated nor changed, and the multipart `image[]` form is still shown in the official edits examples. The only route with an open question is the subscription one (item 1), and this branch answers it conservatively rather than sending an unverified model to it.
